# Capacity Planner 문서

프로젝트의 정책과 구현 규칙은 책임 영역별로 관리합니다.

| 문서                                                 | 범위                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------- |
| [POLICY.md](./POLICY.md)                             | 제품 운영 원칙, 역할과 권한, 작업 상태 전이, 데이터 안전, 개발 정책 |
| [FRONTEND.md](./FRONTEND.md)                         | 프론트엔드 구조, 컴포넌트 경계, 디자인 시스템, 반응형 UI            |
| [BACKEND.md](./BACKEND.md)                           | 서버 아키텍처, API, 인증, 데이터베이스, Telegram 알림               |
| [IMPLEMENTATION_AUDIT.md](./IMPLEMENTATION_AUDIT.md) | 문서 정책과 현재 프로젝트 구현의 차이 및 권장 처리 순서             |

## 문서 관리 원칙

- 정책이 변경되면 코드보다 먼저 또는 같은 변경에서 관련 문서를 갱신합니다.
- README에는 프로젝트 소개와 기술 스택, 실행에 필요한 최소 정보만 둡니다.
- 화면 구현 규칙은 `FRONTEND.md`, 서버 및 DB 구현 규칙은 `BACKEND.md`를 기준으로 합니다.
- 역할, 권한, 상태 전이처럼 프론트엔드와 백엔드가 함께 따라야 하는 규칙은
  `POLICY.md`를 기준으로 합니다.
